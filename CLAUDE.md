# NBD — Discord-бот (музыка) + админ-панель

## Структура
- `main.py` — `MusicBot(commands.Bot)`; грузит расширения из `EXTENSIONS`, синхронизирует слэш-команды, обрабатывает ошибки (`record_error`, уведомления в `ERROR_CHANNEL_ID`).
- `config.py` — все настройки из `.env`; относительные пути считаются от папки бота.
- `cogs/music_cog.py` — вся музыка. Пользовательские команды только слэш (`/play`, `/radio`, `/queue`, ...). Ядро: `_play_next`, `_ensure_voice`, `_enqueue_and_start`, `_full_stop`, `_after`. `apply_volume()` — единственный способ менять громкость играющего трека (учитывает обёртку саундборда).
- `cogs/admin_cog.py` — префиксные команды владельца (`!status`, `!reset`, `!eval`, ...); `cog_check` пускает только `is_owner`.
- `cogs/fun_cog.py` — публичные слэш-команды для развлечения (`/8ball`, `/roll`, `/coin`, `/choose`, `/rate`, `/compliment`, `/joke`).
- `cogs/api_cog.py` — админ-API (aiohttp, HTTP + WebSocket) внутри процесса бота: плеер, плейлисты, саундборд, чат-инструменты, админ-действия, лента событий.
- `utils/sources.py` — yt-dlp, Яндекс.Музыка, радио, создание ffmpeg-источника.
- `utils/queue_manager.py` — `QueueManager` (очереди по серверам) и `GuildState` (состояние плеера).
- `utils/logs.py` — логирование и кольцевой буфер ошибок `ERRORS`.
- `utils/playlists.py` — сохранённые плейлисты владельца в `data/playlists.json`.
- `utils/sounds.py` — звуки саундборда: файлы и индекс в `data/sounds/`.
- `utils/mixer.py` — `MixSource`: подмешивает звуки к играющему треку (PCM 48 кГц стерео, без numpy/audioop), после звука возвращает исходный источник.
- `admin_ui/` — локальная админ-панель: `server.py` (прокси + раздача UI), `rest_backend.py` (режим просмотра через Discord REST), `static/index.html` (весь фронтенд одним файлом, без сборки и зависимостей).
- `tests/test_player.py` — регрессионные проверки ядра плеера и микшера на заглушках (без Discord).
- `MASTER_KEY.txt` — мастер-ключ владельца в открытом виде; только локально, в `.gitignore`, на хост не загружать.

## Модель данных плеера
- Очередь — список dict-треков: `type` (`track`|`radio`), `provider` (`youtube`|`yandex`|`radio`), `title`, `webpage_url`, `duration`, `requester`. `stream_url` и `resolved_at` заполняются лениво в `resolve_item`; ссылка живёт `STREAM_URL_TTL` (10 мин), поэтому плейлисты хранят треки без неё.
- Состояние сервера — `bot.guild_states[guild_id]` (`GuildState`); переживает перезагрузку `MusicCog`.
- `GuildState.started_at` — `time.monotonic()`; паузы не учитываются.
- `loop`: `off` | `track` | `queue`. `force_next` нужен, чтобы skip работал при `loop=track`; также помечает остановку/пропуск как намеренные.
- Защита от зацикливания: трек, оборвавшийся быстрее `QUICK_FAIL_SECONDS`, увеличивает `GuildState.quick_fails`; после `QUICK_FAIL_LIMIT` подряд `_after` вызывает `_halt_broken` (очередь сохраняется). Намеренный skip/stop не считается.
- `_play_next` не теряет треки: при неудачном подключении или если пока трек грузился заиграл звук саундборда, трек возвращается в начало очереди.
- `_ensure_voice` переводит простаивающего бота в `GuildState.voice_channel_id` (канал пользователя), играющего — не трогает.

## Админ-панель и удалённый доступ
- Один токен бота = одно голосовое подключение на сервер и дубли ответов на команды. Второй экземпляр бота с тем же токеном запускать нельзя. Поэтому панель управляет боем на хосте через `api_cog`, а локально запускается только `admin_ui/server.py`.
- `api_cog` грузится и включён всегда (мастер-ключ). Слушает `ADMIN_API_HOST:ADMIN_API_PORT` (по умолчанию `127.0.0.1:8787`); наружу — через SSH-туннель. Если порт занят (старый процесс после перезапуска), `_start_site` повторяет попытку каждые 5 с, бот при этом работает.
- Ошибки Discord в API мапятся в коды: `Forbidden`→403, `NotFound`→404, прочие `HTTPException`→502, таймауты→504, `ApiError` — свой код и текст для UI. Фоновые задачи запускать только через `ApiCog._background` (держит ссылку и пишет исключения в `logs.ERRORS`).
- `GET /api/me` — кто подключён и с какой ролью (`admin`/`guest`); UI прячет недоступное по ролям (`data-admin`) и режиму (`data-full`).
- Аутентификация: `Authorization: Bearer <token>` (для `/ws` допустим `?token=`). Допустимы: мастер-ключ (в коде только `config.MASTER_KEY_HASH` — SHA-256, API включён всегда), `ADMIN_API_TOKEN` (полный доступ) и `ADMIN_GUEST_TOKENS` (без `/api/admin/*`, `/api/logs`, `/api/errors`). Токены — `имя:токен`, несколько через запятую; имя попадает в ленту событий. Минимум 16 символов.
- Режимы панели (`ADMIN_MODE` в `admin_ui/.env`): `remote` — проксирование на API бота; `readonly` — прямой Discord REST по `DISCORD_TOKEN`, без шлюза (хостовому боту не мешает), доступны только серверы, каналы и чат; остальные эндпоинты возвращают 501.
- Саундборд: звук играет через `MixSource`. Если играет музыка, источник оборачивается и возвращается обратно после звука; если тишина, бот сам играет микшер и по завершении запускает ожидающую очередь, уходит по idle-таймеру или (при `leave_after`) сразу отключается. Загрузка — multipart `POST /api/sounds`, проверка через `ffmpeg`, лимит `SOUND_MAX_MB`.
- Чат-инструменты (`/api/guilds/{id}/chat/{action}`): `typing`, `embed`, `poll`, `react`, `edit`, `delete`, `typewriter`, `schedule`. Упоминания `@everyone`/`@here` и ролей разрешены только флагом `allow_mentions` и только полному доступу (гостевой получает 403); в UI флаг сбрасывается после отправки и требует подтверждения. Массовых и спам-действий не добавлять.
- `admin_ui/server.py` подставляет токен сам, проверяет `Host`/`Origin` (защита от DNS rebinding/CSRF) и слушает только localhost. Токен в браузер не попадает.
- В API намеренно нет аналога `!eval`. Новые действия добавлять только осознанно: API управляет живым ботом.
- Админ-действия API дублируют `!`-команды (`sync`, `reload`, `reset`, `leave_all`, `restart`, `update_ytdlp`, ...). При изменении логики в `admin_cog` проверять `api_cog.h_admin`.
- `api_cog` не перезагружается через `reload` (обрывает собственный HTTP-ответ): только перезапуск бота.
- События ленты (`emit`) формируются слушателями `api_cog` и сравнением снимков состояния раз в 2 с.

## Запуск
- Бот: `pip install -r requirements.txt`, `.env` (`DISCORD_TOKEN`, опционально `FFMPEG_PATH`, `COOKIES_FILE`, `DEFAULT_PREFIX`, `YANDEX_TOKEN`, `ERROR_CHANNEL_ID`, `OWNER_IDS`, `IDLE_DISCONNECT_SECONDS`, `ADMIN_API_*`), `python main.py`.
- Панель: `admin_ui/.env` (см. `.env.example`), `python admin_ui/server.py`, открыть `http://127.0.0.1:8080`. Подробности и установка на хост — `admin_ui/README.md`.

## Соглашения
- Язык интерфейса, логов и сообщений — русский.
- Код без поясняющих комментариев; комментарий только там, где причина неочевидна технически (обходы, ограничения Discord/ffmpeg).
- Слэш-команды пользователей не должны раскрывать админ-функции; ошибки префиксных команд для не-владельцев молчат.
- Секреты (`.env`, `cookies.txt`, токены) не логировать и не выводить.
- Проверка: `python tests/test_player.py` (нужны зависимости из `requirements.txt`), затем запуск бота и ручной прогон через панель/Discord.
- UI: всё в `admin_ui/static/index.html`; любые данные из Discord вставлять только через `esc()`; ID Discord приходят строками (`_safe` в API), сравнивать через `==`. Диалоги — `modal()`/`confirmBox()`, не `prompt`/`confirm`. Прямые ссылки: `#<страница>`, `#server/<guild_id>`.
